# Design decisions

- **Toolchain and dependencies.** Go 1.25 is the minimum because the pinned Crewjam SAML dependency requires it. The direct modules are Crewjam SAML, go-jose, and yaml.v3. The remaining entries in go.mod are their transitive dependencies. Aegis implements the OIDC relying-party flow.
- **Listener separation.** The browser listener handles sessions and protocol endpoints. The machine listener requires mTLS and sends every admitted request through machine authorization. This prevents a failed certificate check from falling back to browser credentials.
- **Local logout.** A POST with a session CSRF token invalidates the gateway session. Provider-initiated and federated logout are outside the implemented profile.
- **Browser-bound login state.** Pending records live on the server for five minutes and are consumed once. OIDC stores its verifier and nonce there. SAML stores the request ID and previous session ID. Only the SAML pending cookie is SameSite=None, because the corresponding ACS request is a top-level cross-site POST.
- **JWT profile.** OIDC defaults to RS256, with ES256 and EdDSA available per provider. JWT expiry and issued-at are mandatory. Not-before is checked when supplied. Multi-audience tokens must name the configured client as their authorized party. The gateway signs with ES256 and the demo upstream uses zero verification leeway.
- **JWKS availability and removal.** Successful refreshes replace the whole snapshot. Cache-Control max-age and Age determine freshness with a one-hour ceiling and a five-minute default. Unknown-key refreshes share one in-flight fetch and have a one-second cooldown. Known keys can survive an eligible failed refresh for at most five minutes after expiry. Revalidation-only directives disable stale use. Readiness requires usable fresh keys and rejects discovery drift. It memoizes checks for five seconds.
- **SAML profile.** Support SP-initiated Redirect/POST and one plaintext assertion with an assertion-level signature. Crewjam verifies XML signatures and protocol semantics. Aegis additionally restricts XML shape, checks exact audience and signed recipient/request binding, and tracks assertion IDs. Aegis checks its own deadlines with its injected clock. The library's internal protocol and signature-certificate timers also apply through its process clock.
- **Rule ordering.** The first path-and-method match decides. A denial or missing membership in that rule ends evaluation. Prefix matching is segment-aware. Every listed group and role is required for a browser user and any exact listed machine subject is sufficient for a machine. Aegis trusts both configured human IdPs to assign these policy attributes.
- **Forwarding contract.** An allowlist admits common content and negotiation headers. Aegis derives forwarding metadata from the verified connection and configured public origin. A trusted TCP peer can supply a syntactically valid address chain. Operators must ensure each trusted ingress proxy sanitizes that chain. All inbound transfer encodings are rejected because Go can normalize away a conflicting Content-Length before a handler sees it.
- **PKI scope.** Clients present a leaf issued directly by a dedicated P-256 root and may include that root. The revocation list is a bounded local file with canonical hexadecimal serials. New connections and subsequent mTLS requests read the current list. The TLS reloader publishes a complete validated key pair and keeps the old pair on errors. SIGHUP serves operator-triggered reloads on Unix, with one-second polling for certificate changes.
- **Logs and deployment.** Audit events use fixed method and reason codes, with no token or principal payloads. All runtime identity stores are process-local. Upstream identity is a short-lived bearer assertion and requires network isolation and a trusted hop. The demo binds loopback and uses a disposable CA.
